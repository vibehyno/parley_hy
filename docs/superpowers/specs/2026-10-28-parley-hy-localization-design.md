# Parley HY 브랜딩 및 다국어 UI 설계

## 의도

- 희영 버전 식별성 확보
- 영어 설정 화면의 사용 난이도 완화
- 공개 저장소 배포 시 한국어·영어 사용자 동시 지원

## 확정 범위

- 화면 이름: `Parley HY`
- 저장소 이름: `parley_hy`
- 실행 명령: `parley`
- 대화 저장 위치: `~/.parley`
- 설정 언어: `한국어` / `English`
- 언어 선택값의 브라우저 로컬 저장
- 사이드바, 방 생성, 설정창, Tools, 입력창, 중단·재시도·대기열 등 사용자 조작 화면 번역
- README 상단의 한국어 실행·사용 가이드 추가

## 제외 범위

- 에이전트 내부 계약·제어 프롬프트 번역
- CLI 원문 오류 변조
- 기존 대화·방·세션 저장 형식 변경
- npm 패키지명과 `parley` 실행 명령 변경

## 접근 방식 비교

1. 설정창만 번역: 변경량 최소화, 나머지 화면의 영어 난이도 잔존
2. 사용자 조작 화면 전체 번역: 사용성 개선과 런타임 안정성의 균형
3. 내부 프롬프트·시스템 기록까지 전체 번역: 검증 범위 확대와 프로토콜 회귀 위험 증가

선택안: 2번. 사용자에게 보이는 조작 문구는 번역하고 에이전트 프로토콜과 저장 형식은 유지.

## 구현 원칙

- 중앙 번역 사전 및 `data-i18n` 기반 정적 문구 갱신
- 동적 토스트·상태 문구의 번역 헬퍼 적용
- 언어 변경 즉시 화면 반영
- 기본 언어: 브라우저가 한국어이면 한국어, 그 외 영어
- 사용자가 선택한 언어를 `localStorage`에 저장
- 기존 DOM 식별자, API, 대화 기록, CLI 인자 불변
- 번역 누락 시 영어 원문으로 안전 대체

## 검증 기준

- 한국어·영어 전환 및 새로고침 후 선택 유지
- 주요 설정·Tools·방 생성·입력 화면의 번역 적용
- 기존 852개 회귀 테스트 유지
- 런타임 프로토콜 및 기존 대화 폴더 호환 유지
- 로컬 Parley 재시작 후 기존 방 목록 보존
